第四阶段：个人成长与学习系统 UI / UX 设计

我建议把整个系统的 UI 定位为：

简洁的工作台 + 直观的数据可视化 + 可操作的交互组件。

不是把所有功能都做成表格和文本框，也不是为了视觉效果堆砌大量图表。每个模块都应该有一种最适合它的核心交互方式。

例如：

  • Future Self：用愿景卡片和身份关系图表达未来方向。

  • Roadmap：用多轨道时间线和能力树表达长期发展。

  • Goals & Tasks：用目标树、看板和四象限表达计划与执行。

  • Habits：用福格焦点地图选择值得培养的行为，再用行为设计流程建立习惯。

  • Learning：用 OFRL 流程工作台引导学习，而不是简单填写学习笔记。

  • Review：用数据对比、问题分析和调整面板完成复盘。

一、整体 UI 设计原则

1. 简洁，但不能牺牲交互

我建议每个页面采用三个层次：

第一层

概览层

先看到当前状态、关键数据、主要问题。

例如：本周目标进度、今日任务、近期里程碑。

第二层

可视化操作层

用图形、卡片、拖拽、时间线、矩阵直接操作数据。

例如：拖动行为到焦点地图、调整 Roadmap 节点。

第三层

详情与编辑层

选中对象后，才显示完整字段、说明、关联关系和历史。

使用侧边抽屉、弹窗或独立详情页，而不是一开始展示几十个输入框。

这可以避免页面一打开就被大量字段淹没，同时保证功能完整。

2. 统一页面布局

建议桌面端采用左侧导航、顶部工具栏、中央内容区的布局。

  1. Vision：未来愿景。

  2. Identity：未来身份。

  3. Direction：发展方向。

  4. Motivation：愿景背后的动力。

  • 点击「添加方向」：创建新的发展方向并连接到 Vision。

Motivation 交互

不建议用长篇问卷。

  • 我希望通过它获得什么？

  • 哪个方面让我最有兴趣？

  • 我目前最大的顾虑是什么？

这些内容可以用短文本记录，并在每周或每月复盘时重新查看。

学习工作台必须有主动回忆组件。

  2. 用户先隐藏答案，尝试自己解释。

  3. 用户点击「显示参考内容」。

  4. 用户选择回忆结果：完全不会、部分记得、基本掌握、能够迁移应用。

06 Habits：习惯设计与行为管理

这是我认为需要重点设计的模块。

习惯模块不能只是一个打卡日历。它应该包含：行为发现 → 行为筛选 → 行为设计 → 执行追踪 → M/A/P 诊断。

尤其是你提到的福格模型焦点地图，我建议把它设计成一个真正可以拖拽、排序、评分、选择行为的交互式工具。

A. Focus Map：福格焦点地图

这里采用福格行为设计中的 Focus Mapping 思路：先列出可能的行为，再根据行为的**影响力（Impact）和容易程度（Ease）**进行评估，找出值得优先培养的行为。

注意，它不是把 Motivation、Ability、Prompt 直接当作焦点地图的两个坐标轴。M/A/P 是后续分析某个具体行为能否发生的诊断框架。

C. M/A/P：行为诊断面板

当一个习惯没有发生时，系统不应该直接提示「你不够自律」。

应该让用户分析问题来自哪里。

Behavior Diagnosis

为什么今天没有完成论文阅读？

较低

较高

未触发

系统建议

优先调整 Prompt

尝试把阅读行为绑定到每天打开电脑这一已有事件，而不是依赖固定时间提醒。

正式版应让用户通过滑块、选择项和具体原因记录进行诊断，而不是把这些数值直接当成客观心理测量结果。

M/A/P 的判断应根据实际行为记录、用户反馈和具体情境，提供调整建议：

  • M 低：重新连接个人动机，或换成更有吸引力的行为。

  • A 低：缩小微行为，降低时间、精力和技能门槛。

  • P 低：更换锚点、提醒方式或触发环境。

用户确认后，才更新 Habit 配方。

  1. 今日习惯：一键记录微行为。

  2. 周历：查看每周执行情况。

  3. 趋势：观察执行频率、障碍和难度。

这里不建议只显示连续打卡天数。可以显示：

  • 微行为完成率。

  • 扩展行为完成率。

  • 锚点触发率。

  • 最常见阻碍。

  • M/A/P 问题分布。

这样用户能看到行为为什么发生、为什么没有发生，而不是只看一个连续天数。

三、全局视觉设计规范

为了让七个模块看起来像同一个产品，而不是七个独立网页，需要统一视觉语言。

3.1 整体风格

我建议采用：

Growth OS · Visual Direction

Light

清晰、轻量、专注

Dark

安静、低干扰、耐看

建议支持浅色、深色、跟随系统三种模式。

设计原则：

  • 页面背景使用浅灰或低对比度背景。

  • 内容区域使用白色或深色主题下的深灰。

  • 重要操作使用蓝色。

  • 成功状态使用绿色。

  • 警告状态使用橙色。

  • 风险状态使用红色。

  • 其他信息使用中性灰色。

  • 少用阴影，更多使用留白和细边框。

  • 避免每一个模块都做成卡片。

特别建议：颜色尽量具有统一语义。

例如 Roadmap 中的方向颜色可以固定，而任务状态颜色、重要程度颜色也应该有自己的语义，不能每个页面随意选择颜色。

四、页面交互的几个关键决定

除了页面长什么样，还有几个交互规则建议现在确定。

4.1 采用「概览 → 选择 → 详情」三级交互

例如，在 Roadmap 中：

  1. 打开 Roadmap，看到所有方向的时间线。

  2. 点击科研方向，看到该方向的阶段、里程碑和能力。

  3. 点击某个里程碑，右侧打开详情抽屉。

  4. 在抽屉里查看关联目标、任务、成果和修改历史。

这样用户不会因为查看一个对象而不断跳转页面。

4.3 所有可视化都要有数据来源

例如：

  • Roadmap 的进度来自里程碑、目标和成果。

  • 能力等级来自能力评价记录。

  • Focus Map 来自用户对候选行为的 Impact 和 Ease 评分。

  • 学习趋势来自 LearningSession。

4.4 空状态也要有引导

新用户第一次打开系统时，很多图表没有数据。

不要显示一大片空白，也不要伪造数据。可以显示：

  • 第一步应该做什么。

  • 一个简短的示例。

  • 一个可以立即操作的入口。

例如第一次进入 Focus Map：

「先列出你希望养成的行为，再根据影响力和容易程度筛选。系统会帮助你找到最值得优先设计的行为。」

七、我建议下一步不要急着写所有页面

我们应该先把 UI 设计落实为页面级原型规范，然后再进入 Vue 组件开发。

优先做三个代表性页面：

  1. Dashboard：确定整个系统的布局、导航和信息密度。

  2. Roadmap：确定时间线、能力地图、节点详情的交互方式。

  3. Habits / Focus Map：确定拖拽矩阵、行为评分、行为设计器的完整操作流程。

这三个页面分别代表日常工作台、长期规划和行为设计，能先验证整个系统最重要的 UI 交互模式。

我的建议是先从 Focus Map 页面开始做高保真交互原型：它既能体现福格行为设计的特点，也最能检验我们是否真正做出了一个可操作的成长系统，而不是一个普通的表单管理网站。
